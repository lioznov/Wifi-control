# Как устроен WIFI-control

Этот документ описывает текущую учебную версию проекта. Обновляйте его, когда функции, формат сообщений или поведение программы изменятся.

## Общая схема

- `teacher.py` — панель преподавателя и TCP-сервер.
- `student.py` — приложение ученика, которое собирает заголовки окон и отправляет их серверу.
- На текущем этапе сервер слушает `127.0.0.1:50505`: подключение возможно только с того же компьютера.
- Код доступа проверяется только на длину, стороны не проверяют друг друга, а обмен не шифруется. Закрытие окон ещё не реализовано.

```text
Ученик                                  Преподаватель

connect_to_teacher()                    start_server()
       |                                       |
       v                                       v
try_connection() -- TCP-подключение --> wait_for_students()
       |                                       |
       |                                       v
show_open_windows()                     handle_student()
       |                                       |
       +---- имя и список окон (JSON) -------->|
                                               v
                                         student_events
                                               |
                                               v
                                       check_student_events()
                                               |
                                               v
                                     меню и окна выбранного ученика
```

Пока соединение работает, ученик повторно собирает и отправляет список примерно каждые три секунды. Сервер обрабатывает каждого клиента в отдельном потоке.

## Функции и обработка событий

При выполнении `def` Python создаёт функцию, но её тело запускается только при вызове. После создания окна `app.mainloop()` запускает обработку событий: нажатий кнопок, выбора пункта меню и вызовов, запланированных через `app.after()`.

Сетевые операции могут ждать ответа, поэтому они выполняются в фоновых потоках. Элементы CustomTkinter обновляются в основном потоке. Для передачи событий между потоками используются очереди:

- `connection_results` у ученика — состояние соединения;
- `presence_events` у преподавателя — подключения и отключения;
- `student_events` у преподавателя — полученные имена и списки окон.

Метод очереди `put()` добавляет событие. `get_nowait()` пытается забрать его сразу, не задерживая интерфейс; если очередь пуста, возникает `queue.Empty`. Функции проверки очередей планируют повторный вызов через `app.after()`.

## Программа ученика: student.py

### `show_open_windows()`

Собирает и возвращает список заголовков видимых окон Windows. Создаёт пустой список `window_titles`, получает доступ к библиотеке Windows `user32` через `ctypes` и просит `EnumWindows()` перебрать окна. Для каждого окна Windows вызывает вложенную функцию `process_window()`.

Названия из `excluded_titles` сравниваются без учёта регистра и не попадают в результат. Фильтр основан на точных названиях: он может пропустить служебные окна или скрыть обычное окно с совпадающим заголовком. Результат — заголовки окон, а не все процессы компьютера.

### `process_window(hwnd, extra_data)`

Вложенный обработчик одного окна. `hwnd` — идентификатор окна Windows; `extra_data` сейчас не используется. Обработчик проверяет видимость окна и длину заголовка. Затем создаёт буфер, просит Windows записать в него текст и добавляет подходящий заголовок в список внешней функции. `return True` говорит Windows продолжать перебор.

### `print_open_windows()`

Для учебной проверки вызывает `show_open_windows()`, создаёт пример словаря и выводит JSON в консоль. Она не отправляет данные серверу. Её запуск планируется через `app.after()` после старта окна.

### `connect_to_teacher()`

Обработчик кнопки «Подключиться». Считывает IP-адрес и код, проверяет заполненность и минимальную длину кода. При успешной проверке отключает кнопку и запускает `try_connection()` в фоновом потоке. Проверка длины не подтверждает правильность кода.

### `try_connection(ip_address)`

Подключается к серверу по указанному адресу и порту `50505`. Передаёт состояние соединения в `connection_results`. Пока соединение работает, в цикле получает имя компьютера через `socket.gethostname()`, вызывает `show_open_windows()`, создаёт словарь, превращает его в JSON и отправляет в кодировке UTF-8. Ожидает ответ сервера и делает паузу перед следующей отправкой. При ошибке передаёт событие отключения в очередь.

### `check_connection_result()`

В основном потоке проверяет `connection_results`, показывает состояние в окне и включает кнопку после отключения. Затем планирует следующую проверку через `app.after()`.

## Программа преподавателя: teacher.py

### `start_server()`

Обработчик кнопки «Запустить сервер». Проверяет заполненность и длину кода, запускает `wait_for_students()` в фоновом потоке и отключает кнопку повторного запуска. На текущем этапе код не используется для проверки клиента.

### `wait_for_students()`

Создаёт TCP-сокет, привязывает его к `127.0.0.1:50505` и ожидает подключения через `accept()`. Для каждого клиента запускает отдельный поток `handle_student(connection, address)` и снова ожидает новые соединения. Ошибки запуска сервера выводятся в консоль.

### `handle_student(connection, address)`

Обрабатывает одного клиента. `connection` — сокет соединения; `address` — кортеж IP-адреса и временного порта. При подключении помещает событие в `presence_events`. Затем читает сообщения в цикле, проверяет границу сообщения, ограничение размера и типы данных, разбирает JSON и помещает имя и список окон в `student_events`. После каждого корректного сообщения отправляет ответ. При завершении закрывает соединение и помещает событие отключения в `presence_events`.

### `check_presence_events()`

В основном потоке забирает событие из `presence_events`. При подключении добавляет адрес в множество `connected_students`. При отключении удаляет адрес и связанные с ним имя и список окон. Затем вызывает `update_connected_list()` и планирует следующую проверку.

### `check_student_events()`

В основном потоке забирает адрес, имя компьютера и окна из `student_events`. Для активного подключения сохраняет имя в `students_names`, окна — в `student_windows`, после чего вызывает `update_connected_list()`. Планирует следующую проверку очереди.

### `update_connected_list()`

Формирует пункты меню из активных адресов и известных имён. Словарь `student_choices` связывает отображаемую надпись с адресом подключения. Функция сохраняет текущий выбор, если он доступен; иначе выбирает первое доступное соединение. При отсутствии учеников отключает меню. В конце обновляет поле окон через `show_selected_windows()`.

### `select_student(choice)`

Вызывается при выборе пункта меню. Находит адрес выбранного соединения в `student_choices`, сохраняет его в `selected_student` и вызывает `show_selected_windows()`.

### `show_selected_windows()`

Очищает поле вывода и показывает имя, адрес и последний полученный список окон выбранного ученика. Если ничего не выбрано или список ещё не получен, показывает соответствующую подсказку.

## Как устроено сообщение

Ученик превращает словарь в JSON, кодирует его в UTF-8 и добавляет символ новой строки `\n` как границу сообщения. Пример содержимого:

```json
{"computer_name": "DESKTOP-123", "windows": ["Блокнот", "PyCharm"]}
```

Преподаватель читает сообщение до `\n`, декодирует байты, разбирает JSON и отправляет текстовое подтверждение. TCP передаёт поток байтов, поэтому границу сообщений определяет именно принятое программами правило с новой строкой.

## Последовательность работы

1. Преподаватель запускает сервер; `wait_for_students()` ожидает подключений.
2. Ученик нажимает кнопку; `connect_to_teacher()` запускает `try_connection()`.
3. Сервер принимает клиента, запускает `handle_student()` и передаёт событие подключения в очередь.
4. Клиент собирает окна и отправляет JSON; сервер проверяет данные, передаёт их в очередь и отправляет ответ.
5. Основной поток преподавателя обновляет меню; выбор пункта вызывает отображение окон ученика.
6. Ученик периодически отправляет новый список. После отключения сервер сообщает интерфейсу об окончании соединения.
