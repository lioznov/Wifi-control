# Как работает WIFI-control

Этот документ описывает текущую учебную версию по порядку: от запуска до запроса закрытия окна. Она рассчитана на Windows и локальную проверку на одном компьютере.

## 1. Файлы и важные ограничения

- `teacher.py` создаёт панель преподавателя и TCP-сервер.
- `student.py` создаёт видимый клиент ученика, собирает окна и выполняет запрос закрытия.
- `requirements.txt` содержит внешнюю библиотеку CustomTkinter.
- Сервер слушает только `127.0.0.1:47473`: с других компьютеров подключиться нельзя.
- Стороны подтверждают знание общего кода через HMAC. Это не шифрует дальнейшие данные и не защищает их от подмены; слабый код подвержен подбору по перехваченным данным. До внедрения TLS программа не предназначена для работы в общей сети класса.

## 2. Интерфейс, потоки и очереди

При запуске файла Python объявляет функции, создаёт элементы окна и запускает `app.mainloop()` — цикл обработки нажатий и других событий. Длительное ожидание сети в этом цикле заморозило бы окно. Поэтому сетевые функции запускаются в фоновых потоках `threading.Thread`, а виджеты меняются в основном потоке.

Очереди `queue.Queue` передают результаты между потоками: `put()` добавляет элемент, `get_nowait()` забирает его без ожидания. Если очередь пуста, возникает `queue.Empty`. Интерфейс планирует повторную проверку через `app.after()`.

## 3. Запуск сервера преподавателя

1. Кнопка вызывает `start_server()`. Функция получает код из `code_entry`, проверяет его длину и запускает `wait_for_students(access_code)` в отдельном потоке.
2. `wait_for_students()` создаёт TCP-сокет, вызывает `bind()` и `listen()`, затем ожидает клиентов через `accept()`.
3. Для каждого клиента запускается отдельный поток `handle_student(connection, address, access_code)`. `connection` — сокет клиента, `address` — кортеж его IP-адреса и временного порта.

## 4. Запуск ученика и проверка доступа

1. `connect_to_teacher()` проверяет поля ученика и запускает `try_connection(ip_address, access_code)` в потоке. Состояние интерфейсу передаётся через очередь `connection_results`; её проверяет `check_connection_result()`.
2. Клиент открывает TCP-соединение. Преподаватель вызывает `authenticate_student()`, ученик — `authenticate_teacher()`.
3. Преподаватель создаёт новую случайную строку через `secrets.token_hex()`. Стороны вычисляют HMAC с помощью `create_proof()` и разными префиксами `student:` и `teacher:` подтверждают знание общего кода. Сравнение выполняет `hmac.compare_digest()`.
4. Только после проверки преподаватель добавляет событие подключения в `presence_events`. Неверный код приводит к закрытию соединения. Проверка не заменяет TLS и не подтверждает защиту последующих сообщений.

## 5. Как ученик собирает окна

`show_open_windows()` вызывает функции Windows API через `ctypes`: `EnumWindows()` перебирает окна, а вложенная `process_window()` проверяет видимость, читает заголовок и получает PID через `GetWindowThreadProcessId()`. В список не включаются некоторые названия из `excluded_titles` и окна самого клиента.

Каждая запись — словарь: `{"title": "Блокнот", "handle": 123, "pid": 456}`. `handle` идентифицирует окно, `pid` — его процесс. Фильтр по названию не идеален: служебные окна могут попасть в список. Учебная `print_open_windows()` только печатает данные при запуске и не отправляет их преподавателю.

## 6. Постоянный обмен списком и ответом

1. В цикле `try_connection()` клиент собирает окна, формирует словарь `computer_name` и `windows`, кодирует его через `json.dumps()` и UTF-8 и добавляет `\n` как границу сообщения.
2. `handle_student()` читает строку ограниченного размера, разбирает JSON и проверяет структуру. Данные попадают в `student_events`.
3. `check_student_events()` в основном потоке сохраняет имя и окна по адресу подключения и обновляет интерфейс. `check_presence_events()` обрабатывает подключения и отключения.
4. Сервер извлекает из очереди данного соединения команду или отправляет `{"action": "wait"}`. Клиент обрабатывает ответ и ждёт около трёх секунд до следующего обмена.

TCP — поток байтов: границы вызовов чтения и отправки не являются границами сообщений. Здесь конец каждого сообщения обозначает новая строка. Ограничение размера и проверки формата нужны на принимающей стороне.

## 7. Выбор ученика и окна

`update_connected_list()` формирует выпадающее меню учеников; `select_student()` сохраняет выбранный адрес. `show_selected_windows()` вызывает `update_window_menu()`, которая обновляет видимый список окон: удаляет исчезнувшие строки, добавляет новые и сохраняет выделение существующего окна. `select_window()` сохраняет выбранный словарь с заголовком, handle и PID. При переключении компьютера выбор окна сбрасывается. Внутри используется `ttk.Treeview` из стандартного Tkinter; строки определяются парой handle и PID.

## 8. Запрос закрытия

1. Кнопка вызывает `request_selected_close()`. Функция проверяет выбор и просит подтверждение преподавателя. После подтверждения она повторно проверяет, что окно присутствует в актуальном списке, и кладёт команду в очередь только выбранного соединения. Общий словарь очередей защищён `command_lock`.
2. При следующем обновлении `handle_student()` отправляет этому клиенту JSON-команду `close`, содержащую `title`, `handle` и `pid`. Если команды нет, отправляется `wait`. Пока допускается один ожидающий запрос на соединение.
3. Клиент сравнивает команду с последним отправленным им списком окон. Если записи нет, он отклоняет запрос. Если запись совпала, вызывает `request_window_close(handle, pid)`.
4. `request_window_close()` проверяет тип и диапазон идентификаторов, запрещает широковещательный адрес и собственный процесс клиента, сверяет текущий PID окна и отправляет сообщение Windows `WM_CLOSE` через `PostMessageW`.
5. Клиент включает текст результата в следующее обновление. `handle_student()` передаёт его в `command_results`, а `check_command_results()` показывает его в окне преподавателя.

Сообщение «Запрос на закрытие отправлен» подтверждает, что Windows приняла запрос, но не гарантирует закрытия: приложение может попросить сохранить данные или игнорировать запрос. Окно может измениться между проверкой и отправкой; идентификаторы Windows могут повторно использоваться. Повышенные права приложения также могут помешать отправке. Тестируйте на пустом Блокноте.

## 9. Отключение и повторная проверка

Если клиент закрывается или соединение обрывается, `handle_student()` закрывает сокет и удаляет очередь команд подключения. Событие `disconnected` приводит к удалению ученика из меню. Неотправленные команды не переносятся в следующее соединение. При локальном тесте откройте и закройте два клиента, затем проверьте неверный и верный коды.

Следующие этапы: защищённый канал TLS, проверка в локальной сети, улучшение фильтрации окон и обработки ошибок.
