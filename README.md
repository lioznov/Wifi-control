# WIFI-control

Учебный проект на Python для просмотра открытых окон компьютеров класса. Состоит из панели преподавателя и видимого приложения ученика.

## Текущее состояние

Программы обмениваются списками окон через TCP. Панель показывает подключения и позволяет выбрать компьютер и окно, затем отправить запрос на закрытие. Клиент периодически обновляет список, пока соединение работает.

Это учебная версия для теста на одном компьютере: сервер слушает только `127.0.0.1`. При подключении стороны подтверждают знание общего кода с помощью HMAC, но последующие сообщения не шифруются и не защищены от изменения. Возможен подбор слабого кода по перехваченной проверке. Не используйте эту версию для управления классом или в общей сети до добавления защищённого канала.

## Файлы

- `teacher.py` — панель преподавателя и TCP-сервер.
- `student.py` — окно ученика, поиск окон Windows и TCP-клиент.
- `requirements.txt` — внешние библиотеки Python.
- `.gitignore` — локальные файлы, которые не добавляются в Git.

## Установка в Windows

Требуются Python с tkinter и Git. Склонируйте репозиторий, затем в терминале папки проекта выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

В PyCharm выберите `.venv` в качестве интерпретатора проекта.

## Локальная проверка

1. Запустите `teacher.py`, введите код не короче 12 символов и нажмите «Запустить сервер».
2. Дождитесь сообщения «Сервер ожидает подключения...» в консоли.
3. На том же компьютере запустите `student.py`, введите `127.0.0.1` и **тот же** код, затем нажмите «Подключиться».
4. Выберите подключение в панели преподавателя. Список окон будет периодически обновляться.
5. Для проверки откройте пустой «Блокнот», выберите его строку в списке окон и нажмите «Закрыть выбранное окно». Подтвердите запрос и дождитесь результата.

Команда передаётся при очередном обновлении клиента; результат приходит со следующим обновлением, поэтому он может появиться с задержкой. Сообщение об отправке не гарантирует закрытия: приложение может попросить сохранить изменения или отказаться закрываться. Для проверки нескольких подключений можно запустить несколько экземпляров клиента; имя компьютера будет одинаковым, а порты различными.

## Как устроен обмен

Подробное описание функций и их связей находится в [ARCHITECTURE.md](ARCHITECTURE.md).

1. Клиент и сервер выполняют проверку знания общего кода через `authenticate_teacher()` и `authenticate_student()`.
2. `show_open_windows()` собирает заголовок, идентификатор окна и PID видимых окон Windows.
3. `try_connection()` отправляет имя компьютера и список окон; `handle_student()` отвечает командой ожидания или закрытия.
4. Панель ставит команду в очередь выбранного соединения. Клиент сверяет цель с последним отправленным списком и вызывает `request_window_close()`.
5. Результат возвращается при следующем обмене и показывается в панели преподавателя.
